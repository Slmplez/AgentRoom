# 工作区文件编辑使用独立授权与可恢复保存

2026-10-31 用户明确要求在差异工作区添加行内评论、编辑真实文件并自动保存。已有 Agent 只读工作目录不能自动成为文件写入授权；宿主使用独立的编辑工作区配置，并在公共 Client 与认证接口中检查当前身份、房间和工作区。

用户手动打开工作区变更时，宿主读取受信根目录下有界的真实 Git 差异。客户端不能指定根目录或任意 Git 参数。差异保持原版本用于批注，编辑器另读当前磁盘文件；删除、二进制、不支持或超限文件不伪装成可编辑的完整文本。评论绑定文件、补丁摘要、左右侧及行号，持久保存但不自动发送给 Agent。

自动保存只处理已有、受支持的普通文本文件，拒绝越界及链接路径。读取版本摘要、根目录身份和文件身份用于保存前复核。先持久记录待保存请求，再写同目录临时文件并原子替换，最后记录回执。文件系统与数据库不是同一事务；响应丢失或中断后使用原请求标识及磁盘版本核查，不能无条件覆盖后来修改的文件。

编辑草稿与不可变的在途请求分别保存。同一文档共享保存队列和读取过程，关闭后立即重开不能让旧读取或旧回执覆盖新草稿。输入法组合期间不保存；检测到冲突时暂停自动写入，保留草稿供用户比较或恢复。

标准文件系统接口不能为任意外部编辑器提供跨进程原子比较并替换。最终复核与重命名之间仍存在竞态，因此能力限定于用户信任的本地工作区，并阻止与尚未确认停止的托管任务冲突。这个限制不能用一次成功测试消除。具体支持范围、限额、恢复和真实入口验收见 GitHub #44；模拟文件或独立服务测试不能替代正式宿主接线。
