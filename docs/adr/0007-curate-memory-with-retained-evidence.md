# 后台自动整理记忆，保留原始依据与任务快照

2026-10-31 用户明确要求后台 Agent 自行整理记忆，不逐条等待人工确认。这一授权扩展原来的手动记忆管理；不引入 RAG，也不授权整理员修改各 Agent 的 Soul。

原始记忆、整理后的有效投影和任务启动快照分开保存。原始记录可以持续积累并分页读取；后台整理只在一个 Agent 或 Room 范围内，分批生成合并、更新和归档结论。每个输入都必须被说明，输出保留来源修订、整理理由及执行身份。归档不删除原文，人工停用的墓碑不得被整理结果复活。来源更正或停用立即使依赖旧修订的摘要退出后续加载。

专用整理引擎没有工具权限，配置及凭据由可信宿主管理。调度限制启动次数、间隔、并发、执行时间和输入输出大小；没有新记录时不调用模型。提交前再次核对范围、来源、设置和投影修订。只有明确完成且确认进程已停止才应用结果；失败或未知结果保留历史并停止该轮自动重试，未确认停止时保留执行槽。

新任务按确定性上下文预算加载有效摘要与尚未整理的记录，记录实际修订、整理批次及未加载数量。已经启动的任务继续使用冻结快照。快照新增版本而不重写旧格式，既有回执与请求哈希保持兼容。

这一选择允许模型改变后续任务使用的总结，同时用不可变依据、版本校验和可查看历史保留可追溯性。结构与来源校验不能证明模型总结语义正确；用户仍可更正或停用原始记录并暂停整理。具体限额和完整验收见 GitHub #43；独立模块通过不代表生产调度已经接通。
