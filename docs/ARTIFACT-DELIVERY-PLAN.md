## Module 与 Interface

Artifacts 是 ApplicationRuntime 内部 Module，公开 Interface 继续由运行时的 execute/query 和 AgentRoomClient 承载。该 Module 负责版本规则、内容校验、任务来源、访问范围以及幂等；HTTP/CLI/引擎工具只作为 Adapter。

候选 Interface（名称在 E0 合入后与其命名统一）：

- 执行上下文内 `publishArtifact`：提交 `key`、产物逻辑标识（新建时省略）、`expectedVersion`、标题、`catalogVersion` 与结构化内容。Agent/Task/Run/执行代次身份从宿主已绑定上下文取得，不接受模型自行指定作者或房间。
- 客户端 `artifact` 查询：以 `roomId + artifactId + version` 获取一个不可变版本；目录版本不支持、内容缺失、不可访问各有明确结果。
- 客户端 `artifactVersions` 查询：返回按版本分页的元数据，默认 20、最大 100；不携带全部内容。
- 现有消息投影增加 `artifactRefs`：只含逻辑标识、精确版本、标题、内容类型及状态。完整内容按打开动作读取，不进入每次快照和 SSE。

同一逻辑产物可以有多个版本；旧消息固定引用发布当时的版本。打开“最新版本”是用户显式选择，不能让历史消息暗中变成最新内容。

## 来源与版本

每个版本保存 artifactId、version、workspaceId、roomId、taskId、runId、producerAgentId、execution incarnation、title、catalogVersion、contentHash、byteLength、createdAt 和内容。所有范围由运行时关联推导，不能把可猜测 ID 当作访问凭据。

新建产物的 expectedVersion 为 0；更新必须匹配当前最新版本。两个并发更新只有一个提交，其余返回 conflict；不静默合并或覆盖。幂等键范围为执行身份与发布命令：同 key 同内容返回原回执，同 key 不同内容返回 idempotency_conflict。

Run 已结束、已撤销、旧 incarnation 或不属于该任务的发布一律拒绝，不落入新 Run。Agent 发布报告不自动标记 Task 验收通过；模型轮次结束、产物已保存和任务已验收保持不同事实。

## 存储与提交边界

首版仅接收不超过 256 KiB UTF-8 编码的结构化 JSON，将正文与元数据存入同一 SQLite 数据库。版本、交付消息/引用、事件与幂等回执由 ApplicationRuntime 在同一事务中提交。A0 不引入外部 blob 文件，从而不需要文件 rename 与数据库提交之间的补偿协议。

内容使用校验后的确定性序列化生成哈希；正文保留为不可变版本。读取校验哈希与目录版本，缺失或损坏显示 unavailable，不替换成空报告或示例。迁移失败保留原库，不重置；拒绝较新的未知数据库版本。

进程在事务提交前退出：没有可见版本/消息/回执。提交后回执丢失：查询原 key，返回已提交版本；不得重新运行 Agent 任务。后端重启沿用 E0 的 uncertain 规则，产物存储不产生自动重跑权限。

文件、图片附件、二进制下载和大内容分块另拆行为；256 KiB 上限以上明确拒绝。本阶段没有任意路径读取、导入文件、HTML 下载或公共产物 URL。

## 受限报告目录 v1

采用显式 `catalogVersion: 1`。输入结构只允许 root 和 elements，每个节点仅接受 type、props、children；未知键拒绝。v1 允许 Section、Metrics、Bars、Table 四类。Field、action、事件处理、表达式、绑定、条件执行、HTML、脚本和远程资源均不属于 A0/A1。

| 限制 | v1 默认 |
| --- | --- |
| 编码后正文大小 | 256 KiB |
| 节点数 / 树深度 | 100 / 8 |
| 标题 / 普通文本 / 表格单元格 | 200 / 4000 / 2000 字符 |
| 指标项 / 图表项 | 每节点最多 20 / 50 |
| 表格列 / 行 | 每表最多 20 / 200；每行长度必须匹配列数 |
| 图表数值 | 有限数，0–100；文本同时显示数值 |

root 必须存在；节点必须可达、无环、无共享子节点；仅 Section 可以拥有 children。字符串按文本渲染，不解析 HTML 或执行 Markdown 内嵌代码。重复节点键、危险对象键及超限输入在提交前拒绝。HTTP 层还需在 JSON.parse 前限制总请求大小，避免仅靠后置 schema 校验。

目录校验以平台无关契约为单一事实来源；前端 registry 只绑定受信任组件。不能直接把现有示例的宽松 schema 当作不可信模型内容校验器。以上限制是可调整的实现默认值，正式票据需包含相同验收值。

## UI 行为

- 仅有真实 artifactRefs 的消息显示产物入口；普通聊天不附空报告或示例按钮。
- 打开后显示标题、版本、Task/Run 来源、发布时间和只读内容。支持历史版本列表及返回原消息。
- 切换房间、产物或版本时丢弃旧查询结果；加载、不可访问、内容缺失、目录不支持分别展示，错误不伪装成空内容。
- 新版本只提示可查看，不替换当前正在看的版本，不覆盖聊天草稿；窄屏返回、Escape、焦点归还和 reduced-motion 沿用既有约定。
- 本机 owner 权限由后端校验；未来多人接入时复用房间授权。不得把“按钮隐藏”作为读取保护。
- 原有“结果示例”保留在明确的 Mock 演示入口，不能伪装成真实任务产物。A1 验收使用真实数据库、真实消息引用和真正的版本查询。

## 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 真实 Agent 发布报告 | 正确的 Task/Run/Agent 身份，生成可追溯交付消息与版本 |
| 修改客户端/模型提交的身份字段 | 拒绝；不能越房间、越任务发布或读取 |
| 相同 key 重试、同 key 改内容 | 原回执 / 冲突；一个版本和一个交付事件 |
| 两客户端同时更新版本 | 一个成功、一个 conflict，旧版内容不变 |
| 节点循环、超深、未知组件、脚本/动作 | 提交前拒绝；无部分写入和事件 |
| 提交前/后故障及重启 | 回滚全部 / 原回执可查，均不重跑 CLI |
| 撤销及旧执行代次晚到 | 拒绝写入当前任务，不满足任何新等待 |
| SSE 断线、事件过期、历史分页 | 快照/历史仍含精确引用，正文按需读取 |
| 内容损坏或目录版本不支持 | 明确 unavailable/unsupported，显示来源元数据但不渲染伪造内容 |
| 切房间/版本时旧请求晚到 | 不污染当前面板，保留用户草稿与阅读位置 |

验证分层为契约/运行时事务、真实 HTTP/SSE 双客户端与子进程故障、真实 CLI 产出、桌面/Web UI。模拟工具流只能证明适配契约，不替代真实 Agent 产出验证。
